프로그래밍을 배우다 보면 이런 의문이 생깁니다.

> "컴퓨터는 어떻게 내 코드를 이해하는 걸까?"  
> "메모리는 뭐고, CPU는 정확히 무슨 일을 하는 걸까?"

이 글은 그 질문에 답합니다.  
코드를 잘 짜려면 컴퓨터가 무엇인지 알아야 합니다. 도구를 이해하는 사람이 도구를 잘 씁니다.

---

## 컴퓨터는 오직 0과 1만 안다

여기서 출발해야 합니다.

컴퓨터 내부의 모든 것 — 숫자, 글자, 이미지, 음악, 게임 — 은 결국 **0과 1의 조합**입니다.

왜 0과 1인가? 전기 때문입니다.

컴퓨터의 기본 부품인 **트랜지스터(Transistor)**는 전기가 흐르는 상태와 흐르지 않는 상태, 딱 두 가지만 가집니다.

- 전기 흐름 → **1 (ON)**
- 전기 없음 → **0 (OFF)**

이 두 상태를 **비트(bit)**라고 합니다.  
비트가 모여서 숫자가 되고, 숫자가 모여서 글자가 되고, 글자가 모여서 프로그램이 됩니다.

---

## 이진법 (Binary)

우리가 평소 쓰는 십진법은 0~9, 10가지 기호를 씁니다.  
컴퓨터가 쓰는 이진법은 0과 1, 2가지 기호만 씁니다.

십진수 13을 이진수로 바꿔보겠습니다.

```
13 ÷ 2 = 6 ... 나머지 1
 6 ÷ 2 = 3 ... 나머지 0
 3 ÷ 2 = 1 ... 나머지 1
 1 ÷ 2 = 0 ... 나머지 1

나머지를 거꾸로 읽으면: 1101
```

확인:  
**1101₂ = 1×2³ + 1×2² + 0×2¹ + 1×2⁰ = 8 + 4 + 0 + 1 = 13** ✓

| 십진수 | 이진수 |
|---|---|
| 0 | 0000 |
| 1 | 0001 |
| 5 | 0101 |
| 10 | 1010 |
| 15 | 1111 |
| 255 | 11111111 |

255가 `11111111`인 이유 — 8비트로 표현할 수 있는 최대값이 255이기 때문입니다.  
8비트(1바이트)는 2⁸ = 256가지를 표현합니다 (0~255).

## 글자는 어떻게 저장하는가: ASCII와 Unicode

컴퓨터는 글자도 숫자로 저장합니다.  
어떤 숫자가 어떤 글자인지 **약속**을 정한 것이 **문자 인코딩(Character Encoding)**입니다.

**ASCII** (American Standard Code for Information Interchange)는 가장 오래된 약속입니다.

| 문자 | ASCII 코드 (십진수) | 이진수 |
|---|---|---|
| 'A' | 65 | 01000001 |
| 'B' | 66 | 01000010 |
| 'a' | 97 | 01100001 |
| '0' | 48 | 00110000 |

그래서 C언어에서 이런 코드가 동작합니다.

```c
char ch = 'A';
printf("%d\n", ch);   // 출력: 65
printf("%c\n", ch+1); // 출력: B  (65+1=66='B')
```

ASCII는 영어만 담았기 때문에 한글, 중국어 등을 표현하지 못했습니다.  
이를 해결한 것이 **Unicode(UTF-8)**로, 현재 전 세계 대부분의 시스템이 사용합니다.  
'가'는 UTF-8에서 `0xEAB080` (3바이트)로 저장됩니다.

## 컴퓨터의 하드웨어 구성

```
┌────────────────────────────────────────────┐
│                  컴퓨터                      │
│  ┌──────────┐   ┌──────────┐               │
│  │   CPU    │◄──►│  메모리   │               │
│  │(처리장치) │   │  (RAM)   │               │
│  └──────────┘   └──────────┘               │
│       │                                     │
│  ┌────▼────────────────────────────────┐   │
│  │         저장장치 (SSD/HDD)           │   │
│  └─────────────────────────────────────┘  │
│  ┌────────────┐  ┌──────────────────────┐  │
│  │    GPU     │  │ 입출력 장치(키보드 등) │  │
│  └────────────┘  └──────────────────────┘  │
└────────────────────────────────────────────┘
```

### CPU (Central Processing Unit) — 뇌

CPU는 계산을 합니다. 덧셈, 뺄셈, 비교, 데이터 이동 — 이것밖에 못합니다.  
하지만 **1초에 수십억 번** 합니다.

CPU 내부에는 **레지스터(Register)**라는 아주 빠른 임시 저장소가 있습니다.  
계산할 때 메모리에서 값을 레지스터로 가져와서 계산하고, 다시 메모리에 씁니다.

```
int a = 3, b = 5;
int c = a + b;

// CPU가 실제로 하는 일:
// 1. 메모리에서 a(3)를 레지스터 R1으로 복사
// 2. 메모리에서 b(5)를 레지스터 R2로 복사
// 3. R1 + R2 를 계산해서 결과(8)를 R3에 저장
// 4. R3의 값을 메모리의 c 위치에 씀
```

### 메모리 (RAM) — 작업대

CPU가 현재 작업 중인 데이터를 임시로 올려놓는 곳입니다.  
전원을 끄면 사라집니다(휘발성).

프로그램을 실행하면 먼저 저장장치에서 메모리로 올라온 뒤 CPU가 처리합니다.

| 종류 | 속도 | 용량 | 전원 끄면 |
|---|---|---|---|
| CPU 레지스터 | 매우 빠름 | 수십 바이트 | 사라짐 |
| L1/L2 캐시 | 빠름 | 수 MB | 사라짐 |
| RAM | 보통 | 8~64GB | 사라짐 |
| SSD | 느림 | 수백GB~수TB | 남음 |

### 저장장치 (SSD/HDD) — 창고

전원을 꺼도 데이터가 남습니다(비휘발성).  
파일, 운영체제, 프로그램이 여기 저장됩니다.

---

## 운영체제가 하는 일

운영체제(OS)는 하드웨어와 프로그램 사이의 **중간 관리자**입니다.

우리가 `hello.c`를 컴파일해서 실행하면:

1. OS가 SSD에서 `hello` 실행파일을 RAM으로 복사
2. OS가 CPU에게 "이 프로그램 실행해"라고 명령
3. CPU가 명령어를 순서대로 실행
4. `printf`를 만나면 OS에게 "화면에 출력해줘" 요청
5. OS가 드라이버를 통해 모니터에 출력

이렇게 OS가 없다면 프로그램마다 모니터, 키보드, 파일 시스템을 직접 제어해야 합니다.  
OS가 이것을 공통으로 처리해주기 때문에 우리는 `printf` 한 줄로 화면 출력을 할 수 있습니다.

---

## 프로그램이 실행되는 과정 전체

```
[소스코드 작성]
  hello.c
       ↓ 전처리기 (Preprocessor)
  #include 처리, 매크로 치환
       ↓ 컴파일러 (Compiler)
  어셈블리 코드
       ↓ 어셈블러 (Assembler)
  오브젝트 파일 (.o)
       ↓ 링커 (Linker)
  실행 파일 (hello)
       ↓ 로더 (Loader, OS)
  메모리에 적재
       ↓ CPU 실행
  화면 출력!
```

IDE나 `gcc` 명령어가 이 과정 전체를 한 번에 처리해줍니다.

## 정리

- 컴퓨터는 **0과 1(비트)**만 이해합니다 — 모든 정보는 이진수로 표현됩니다
- **8비트 = 1바이트**, 1바이트로 0~255를 표현합니다
- 글자는 **ASCII/Unicode** 표준에 따라 숫자로 저장됩니다
- **CPU**는 계산, **RAM**은 임시 저장, **SSD**는 영구 저장 역할을 합니다
- **운영체제**는 하드웨어와 프로그램 사이의 중간 관리자입니다
- 소스코드는 전처리 → 컴파일 → 어셈블 → 링크 → 실행의 과정을 거칩니다

다음 글에서는 **메모리 구조(스택과 힙)**를 다룹니다.  
이것을 이해하면 변수가 어디에 저장되는지, 왜 포인터가 필요한지 보이기 시작합니다.
