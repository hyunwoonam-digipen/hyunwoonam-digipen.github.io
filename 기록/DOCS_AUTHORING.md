# Google Docs 작성 규약

글은 Google Docs에서 완성하고, 변환기를 돌려 블로그 글로 옮긴다.

**Docs 문서가 원본이자 검증 문서다.** Docs만 열어도 이미지까지 포함된 완성된 글로 읽혀야 한다.
그래서 변환용 마커를 쓰지 않는다. Docs의 기본 서식(제목 스타일, 표, 이미지, 등폭 글꼴)만 쓰고,
변환기가 그 서식을 읽어서 마크다운으로 옮긴다.

`_posts/*.md`는 **생성물**이다. 직접 고치지 않는다. 고치면 다음 변환에서 덮인다.

관련 문서: [WRITING_GUIDE.md](WRITING_GUIDE.md) (글 내용 규칙) · 변환기 `tools/docs2post.py`{: .filepath }

---

## 1. 파이프라인 — 역할 분담

Drive의 **업로드 변환**(업로드된 파일을 Google 문서 편집기 형식으로 변환) 설정을 켜둔 상태를 전제로 한다.

| 단계 | 하는 일 | 주체 |
| --- | --- | --- |
| 1 | 원고 유형 확정: 기존 원고 리포맷(유형 A) 인지 신규 작성(유형 B) 인지 | 사용자·Claude |
| 2 | PDF·강의자료·참고 링크·원본 문서 제공 | 사용자 |
| 3 | 초안 작성 — 유형 A는 [WRITING_GUIDE.md 1장](WRITING_GUIDE.md) 리포맷 규칙, 유형 B는 10장 대장·중복 규칙 적용 | Claude |
| 4 | 초안 검토 → 승인 또는 수정 요청 | 사용자 |
| 5 | 승인된 초안을 Docs 업로드용 HTML로 변환 (이미지 내장) | Claude |
| 6 | HTML을 Google Drive에 업로드 → 자동으로 Google 문서로 변환됨 | 사용자 |
| 7 | Docs에서 직접 수정·보강, 완성 | 사용자 |
| 8 | 완성된 Docs 문서 전달 (링크 또는 파일) | 사용자 |
| 9 | Docs → HTML 내보내기 → `docs2post.py` → `_posts/*.md` + 이미지 | Claude |
| 10 | 로컬 렌더 확인 → 커밋 | Claude / 사용자 |

**Claude는 Drive에 파일을 직접 만들지 않는다.** 4단계에서 만든 HTML을 파일로 넘기면, 사용자가 Drive에 업로드해 Docs로 변환한다. 커넥터로 문서를 만드는 방식은 쓰지 않는다 — 이미지 포함 시 용량 문제도 있고, 이 흐름에서는 5~6단계를 사용자가 직접 하는 게 자연스럽다.

**8단계에서 받는 방법 두 가지:**

| 방법 | 사용자가 하는 일 |
| --- | --- |
| 링크 전달 | Docs 링크를 채팅에 붙여넣기 → Claude가 Drive 커넥터로 읽음 |
| 파일 전달 | Docs → 파일 → 다운로드 → **웹페이지(.html, 압축됨)** → 그 파일 전달 |

## 2. 변환 명령

```bash
python tools/docs2post.py "다운로드한파일.zip"
```

`.zip`을 그대로 넣어도 되고, 압축을 풀어 `.html`을 넣어도 된다.
문법만 검사하고 파일은 안 만들 때:

```bash
python tools/docs2post.py "다운로드한파일.zip" --check-only
```

## 3. Docs 설정 — 먼저 끄고 시작한다

Docs 자동 대체가 코드를 망가뜨린다. **도구 → 환경설정 → 자동 대체**에서 아래를 끈다.

- [ ] 스마트 따옴표 (`"` → `“ ”`) — 켜져 있으면 C# 문자열이 컴파일 안 되는 코드로 바뀐다
- [ ] 자동 대문자
- [ ] 하이픈 → 대시 자동 변환

## 4. 서식 매핑 — 이게 전부다

| Docs에서 | 블로그 결과 |
| --- | --- |
| **제목 1** | `##` (개념 단위, 본문 최상위) |
| **제목 2** | `###` (개념 하위) |
| 제목 3 이하 | `####` — **쓰지 말 것**, 변환 시 경고 |
| 일반 텍스트 | 문단 |
| **굵게** / *기울임* | `**` / `_` |
| 글머리기호 / 번호 목록 | `-` / 들여쓰기 유지 |
| 표 | 마크다운 표 (4열 이하) |
| 링크 | `[글자](주소)` |
| **등폭 글꼴 문단** | 코드 블록 |
| **등폭 글꼴 일부 글자** | `` `인라인 코드` `` |
| 삽입한 이미지 | 자동 추출 → `assets/img/posts/<슬러그>/img-NN.png` |
| 이미지 바로 아래 *기울임* 문단 | 이미지 캡션 |
| 문단 맨 앞 `참고:` `팁:` `주의:` `금지:` | Chirpy 알림 박스 |

> 변환기가 **모든 제목을 한 단계 내린다.** Docs 제목1이 블로그 H2가 된다.
> 문서 제목(Title 스타일)은 쓰지 않는다. 제목은 메타 표에 적는다.

## 5. 메타 표 — 문서 맨 위 첫 번째 표

문서 맨 앞에 2열짜리 표를 하나 놓는다. 변환기가 이 표를 front matter로 바꾸고 본문에서 뺀다.

| 항목 | 값 |
| --- | --- |
| 제목 | C# 01 — 프로그래밍과 C# 소개 |
| 날짜 | 2026-08-30 21:00:00 +0900 |
| 카테고리 | C#, 입문 |
| 태그 | csharp, dotnet, il, jit |
| 슬러그 | csharp-01-intro |
| 다이어그램 | true |

| 키 | 필수 | 설명 |
| --- | --- | --- |
| 제목 | ✅ | `C# NN — 제목` 형식 |
| 날짜 | ✅ | 시각과 `+0900`까지. 파일명 날짜가 여기서 나온다 |
| 카테고리 | ✅ | 쉼표로 2개. 3개 이상이면 경고 |
| 슬러그 | ✅ | 파일명·이미지 폴더명. 영문 소문자·하이픈 |
| 태그 | | 쉼표 구분 3~6개 |
| 수식 / 다이어그램 | | 쓸 때만 `true` |
| 썸네일 / 썸네일 설명 | | 대표 이미지 파일명 |
| 기본 언어 | | 코드 블록 기본 언어 (없으면 `csharp`) |

## 6. 코드 — 등폭 글꼴로 쓴다

코드로 쓸 문단을 선택하고 글꼴을 **Roboto Mono**(또는 Consolas, Courier New)로 바꾼다.
연속된 등폭 문단은 하나의 코드 블록으로 묶인다.

**언어는 자동 판별한다.**

| 판별 결과 | 조건 |
| --- | --- |
| `mermaid` | 첫 줄이 `flowchart`, `graph`, `sequenceDiagram` 등으로 시작 |
| `text` | 바로 앞 문단이 `실행 결과` / `출력 결과` / `결과` |
| `bash` | 모든 줄이 `dotnet`, `code `, `cd `, `git ` 등으로 시작 |
| 그 외 | 메타 표의 `기본 언어`, 없으면 `csharp` |

실행 결과를 보여줄 때는 **`실행 결과`라고 쓴 문단**을 먼저 놓고 그 아래에 등폭 문단을 둔다.

> mermaid 다이어그램을 쓰면 메타 표의 `다이어그램`을 `true`로 해야 한다.
> 안 하면 변환이 오류로 막힌다.

## 7. 이미지 — Docs에 직접 넣는다

Docs 문서가 검증 문서이므로 **이미지는 자리표시자가 아니라 실제로 삽입한다.**

1. 이미지를 문서에 삽입한다.
2. 이미지 우클릭 → **대체 텍스트** 에 설명을 적는다. 이게 블로그의 `alt`가 된다. **비면 변환이 오류로 막힌다.**
3. 이미지 바로 아래 줄에 캡션을 쓰고 **기울임**을 준다. 캡션이 필요 없으면 생략한다.

변환기가 이미지를 꺼내 `assets/img/posts/<슬러그>/img-01.png` 순서대로 저장하고 경로를 연결한다.
파일명은 문서에 나온 순서를 따른다. 직접 이름을 정하지 않는다.

## 8. 알림 박스 — 문단 맨 앞 한 단어

| Docs 문단 시작 | 결과 |
| --- | --- |
| `참고:` | `.prompt-info` |
| `팁:` | `.prompt-tip` |
| `주의:` | `.prompt-warning` |
| `금지:` | `.prompt-danger` |

Docs에서도 자연스럽게 읽히고, 변환기가 알아서 박스로 바꾼다. 연속 3개 이상은 쓰지 않는다.

## 9. 변환기가 자동으로 하는 것

- 메타 표 → front matter, 파일명(`날짜-슬러그.md`) 결정
- 모든 제목 한 단계 내리기
- 등폭 문단 → 코드 블록, 언어 자동 판별
- 이미지 추출·저장·경로 연결, 캡션 붙이기
- 빈 줄 3개 이상을 1개로

## 10. 변환기가 막는 것 (오류 → 파일 안 만듦)

- 메타 표에 `제목` / `날짜` / `카테고리` / `슬러그` 누락
- `학습 목표` 섹션 없음
- 금지 섹션 사용: `왜 배우는가`, `직접 해보며 확인한 것`, `궁금했던 점`, `확인 방법`
- `학습 목표`에 체크박스 사용
- 이미지 대체 텍스트가 비어 있음
- mermaid를 썼는데 메타 표의 `다이어그램`이 `true`가 아님

## 11. 경고 (파일은 만들되 확인 필요)

- H4 이상 사용 (Docs 제목3 이하)
- `카테고리`가 2개가 아님
- 표 열 5개 이상
- 스마트 따옴표 잔존
- 언어 태그 없는 코드 블록

## 12. 작성 순서 체크리스트

- [ ] Docs 자동 대체 3종 껐는가 (3장)
- [ ] 문서 맨 위에 메타 표를 넣었는가
- [ ] 제목1로 개념을 잡았는가 (Title 스타일 미사용)
- [ ] 코드 문단을 등폭 글꼴로 바꿨는가
- [ ] 실행 결과 앞에 `실행 결과` 문단을 놓았는가
- [ ] 모든 이미지에 대체 텍스트를 넣었는가
- [ ] 캡션에 기울임을 줬는가
- [ ] `--check-only`로 검사를 통과했는가
- [ ] 변환된 `_posts/*.md`를 열어 눈으로 확인했는가

## 13. 주의

- **생성된 md를 직접 수정하지 않는다.** 수정은 Docs에서 하고 다시 변환한다.
- Docs 문서 하나 = 블로그 글 하나.
- 변환기는 덮어쓴다. 같은 슬러그·날짜로 두 번 돌리면 이전 파일이 사라진다.
- 이미지도 덮어쓴다. Docs에서 이미지 순서를 바꾸면 파일 번호가 다시 매겨진다.
